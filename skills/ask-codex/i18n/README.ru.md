# Ask Codex

**Прямой `read-only` мост из Claude Code, Antigravity или терминала к глубоким рассуждающим моделям OpenAI — без ручного копипаста кода между окнами.**

---

## Какую проблему решает навык

Быстрые ежедневные агенты отлично ориентируются по файлам, правят код и гоняют тесты — ровно до тех пор, пока не упираются в коварную гонку данных, неочевидный инвариант стейт-машины или сложную архитектурную развилку, где начинают ходить по кругу.

Обычно попытка получить второе мнение выглядит плохо:
1. Приходится руками копировать куски кода из IDE в другое приложение и переносить ответ обратно.
2. Внешняя модель не видит соседних файлов проекта и выдаёт оторванную от реальности теорию.
3. Зашитые в самописные скрипты названия моделей устаревают каждые несколько недель с выходом новых релизов.

**Ask Codex** собирает это в аккуратный навык и консольную утилиту:

- **Строгий `read-only` и чистый вывод:** запускает `codex exec --skip-git-repo-check --ephemeral -s read-only` — Codex может сам прочитать нужные файлы в рабочей папке проекта, не мусорит в истории сессий, **физически не может изменить файлы** и печатает чистый ответ в `stdout`.
- **Критическая сверка с проектом, а не слепая вера:** промпт навыка ([`SKILL.md`](../SKILL.md), [перевод](SKILL.ru.md)) учит основного агента передавать сжатый контекст без лишних секретов, а затем проверять гипотезы и риски из ответа Codex на реальном коде проекта, прежде чем что-то менять.
- **Быстрое переключение моделей по подстроке:** смотрите локальный кэш моделей (`--models`), сохраняйте дефолтную модель (`--set`) или разово вызывайте старшую модель (`-m`) без правки промптов.
- **Автопоиск бинарника в `ChatGPT.app` на macOS:** сначала проверяет встроенный бинарник `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`, а затем ищет `codex` в `PATH`.

## Два способа работы

### 1. Прямо в чате с вашим агентом (Claude Code, Antigravity, Codex)

После установки из [корня репозитория](../../../i18n/README.ru.md) просто попросите агента подключить независимый взгляд:

> *«Мы попробовали два фикса для этого дедлока, оба не взлетели. Спроси независимое мнение у Codex, прежде чем снова править файлы.»*

> *«Перед рефакторингом расчёта комиссий проверь через Codex краевые случаи с нулевой ликвидностью и пылевыми остатками.»*

Агент сам соберёт релевантный код и ограничения проекта, вызовет `ask-codex`, проверит утверждения по кодовой базе и прозрачно разберёт спорные места.

### 2. Напрямую из терминала

Посмотреть модели в локальном кэше и текущую выбранную модель:

```bash
ask-codex --models
ask-codex --current
```

Выбрать модель по умолчанию — по полному имени или уникальной подстроке (например, `terra` или `sol`):

```bash
ask-codex --set gpt-6.1-terra
ask-codex --current
```

Или переключить дефолт на Sol:

```bash
ask-codex --set gpt-6.1-sol
ask-codex --current
```

Находясь в папке проекта, запустить безопасный аудит без риска изменения файлов:

```bash
ask-codex "Посмотри этот проект и назови три самые важные проблемы. Файлы не изменяй."
```

Разово вызвать Sol на сложный вопрос, не меняя сохранённую модель:

```bash
ask-codex -m gpt-6.1-sol "Проверь, может ли cancel_order нарушить инвариант баланса при параллельных исполнениях."
```

Передать объёмный промпт из файла через `stdin`:

```bash
ask-codex < prompt.txt
ask-codex -m gpt-6.1-sol < prompt.txt
```

*(Имена моделей приведены для примера — если в вашем аккаунте другой набор моделей, возьмите имя из вывода `ask-codex --models`.)*

## Настройка и приоритет выбора модели

| Флаг / Переменная | Как работает |
| :--- | :--- |
| `-m <model>` / `--model <model>` | Максимальный приоритет: выбирает модель только для текущего запуска. |
| `ASK_CODEX_MODEL` | Переменная окружения; перекрывает сохранённый в файле выбор. |
| `ask-codex --set <model>` | Сохраняет постоянный выбор в `~/.codex/active_partner_model`. |
| *(Модель не задана явно)* | Используется собственная дефолтная модель, настроенная в Codex CLI. |
| `CODEX_HOME` | Меняет базовую директорию Codex (по умолчанию `~/.codex`) и для `models_cache.json`, и для `active_partner_model`. |

### Полезно знать

- **Требования:** установите симлинки через `./install.sh` из [корня репозитория](../../../i18n/README.ru.md). Codex CLI должен быть установлен и авторизован; рабочие способы авторизации и доступ к конкретным моделям зависят от вашей настройки и аккаунта Codex.
- **Поиск по подстроке:** короткое имя (например, `terra` или `sol`) сработает, если ему соответствует ровно одна модель в `models_cache.json`. При неоднозначности утилита сразу покажет список совпадений. Если файла кэша ещё нет, имя передаётся в Codex как есть.
- **Актуальность кэша:** `models_cache.json` отражает локальный кэш Codex — он может устареть и сам по себе не гарантирует доступ аккаунта к модели.
- **Всегда перепроверяйте:** воспринимайте ответ Codex как сильное второе мнение и сверяйте выводы с реальным кодом проекта перед внесением изменений.
