# Контекст для аудита OpenAI Codex: Архитектура тандема и библиотека навыков

## 1. Предыстория и предпосылки
У пользователя (Senior Software Engineer, 14 000+ часов на Upwork, 270+ закрытых контрактов в финтехе, Web3 и траблшутинге) на рабочей машине одновременно работают два ИИ-инструмента:
1. **Основной IDE-агент** (Antigravity / Claude Code / Cursor) — быстрый, прагматичный, отлично работает с локальной файловой системой, терминалом и тестами, но упирается в предел рассуждений на глубокой математике, формальных инвариантах и сложных протоколах.
2. **OpenAI Codex / ChatGPT Pro** с доступом к передовым рассуждающим моделям (`gpt-6.1-terra`, `gpt-6.1-sol`, `gpt-6-astra`).

**Проблема:**
- Ручной копипаст кода между окном IDE и десктопным ChatGPT отнимает время и контекст.
- Рассуждающие модели OpenAI обладают высочайшим интеллектом, но склонны к академическому оверинжинирингу, гиперперестраховке, многословию и созданию «сферических коней в вакууме» (теоретически безупречные решения, неприменимые в реальном коде без доработки напильником).
- Модели быстро обновляются: хардкод имен моделей в промптах и скриптах ломается каждые несколько недель.

## 2. Разработанная архитектура тандема

```
                    ┌─────────────────────────┐
                    │     Задача / Проблема   │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │    Основной агент       │
                    │    (Antigravity/Claude) │
                    └──────┬───────────▲──────┘
      1. Сжатый контекст   │           │  3. The Grounding Protocol
         и точный вопрос   │           │     (фильтр «сферических коней»)
                           ▼           │
                    ┌──────────────────┴──────┐
                    │   OpenAI Codex CLI      │
                    │   (gpt-6.1-terra / sol) │
                    │   "The Deep Thinker"    │
                    └─────────────────────────┘
```

### Распределение ролей:
* **Codex ("The Deep Thinker"):** сложная алгоритмическая геометрия, инварианты распределенных стейт-машин, криптографические протоколы, поиск нетривиальных race conditions и векторов атак.
* **Antigravity ("The Grounding Partner"):** точная формулировка проблемы с граничными условиями реального проекта, перехват вывода Codex, беспощадное отсечение академической воды и перестраховок, перевод на человеческий язык и внедрение в кодовую базу с прогоном тестов.

### The Grounding Protocol (Обязательный фильтр из 5 шагов):
1. **Extract Core Insights:** извлечь фундаментальное математическое/логическое зерно.
2. **Filter Out Fluff / "Spherical Cows":** отбросить избыточные абстракции и гипотетические оговорки, нарушающие реальные инварианты системы.
3. **Map to Codebase:** приземлить решение на реальные типы и библиотеки репозитория.
4. **Human Translation:** объяснить суть пользователю простыми словами.
5. **Implement & Test:** написать код и запустить проверку тестами.

## 3. Техническая реализация моста (`ask-codex`)

1. **Использование нативного CLI из `ChatGPT.app`:**
   Вместо отдельного API-ключа используется бинарник `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`. Запросы идут неинтерактивно (`codex exec --ephemeral -s read-only -o <out_file>`), не требуют отдельной оплаты API и используют активную подписку пользователя.
2. **Динамический переключатель моделей без переписывания навыков:**
   Скрипт `ask-codex` читает живой список доступных в аккаунте моделей из `~/.codex/models_cache.json`:
   - `ask-codex --models` — выводит живой список и текущую активную модель.
   - `ask-codex --set <part_of_name>` — переключает дефолт (сейчас установлен `gpt-6.1-terra` как оптимальный по соотношению интеллект/скорость/лимиты).
   - `ask-codex -m sol "..."` — разовый вызов старшей модели `gpt-6.1-sol` для тяжелых доказательств.

## 4. Структура репозиториев навыков

1. **Публичный репозиторий (`dmatora/agent-skills` на GitHub):**
   - Навык `codex-sol` (с документацией на двух языках, `SKILL.md`, `README.md`, `i18n/`).
   - Исполняемые файлы `bin/codex` и `bin/ask-codex` (с симлинками `ask-sol`, `ask-terra`).
   - Идемпотентный установщик `install.sh`, разворачивающий симлинки в `~/.local/bin/`, `~/.gemini/config/skills/`, `~/.claude/skills/` и `~/.gemini/GEMINI.md`.
2. **Приватный репозиторий (`agent-skills-private`):**
   - Навык `cognitive-debt` (протокол устранения когнитивного долга после генерации агентов: 7 рычагов, дозирование по одному слою, запрет ASCII-схем, голосовой бриф через MCP память на обеде). Находится на полевом тестировании перед публичным релизом.
   - Навык `upwork-seeking` (проприетарный скоринг вакансий).

## 5. Вопросы для аудита Codex

1. **Баланс ролей:** Насколько адекватно описан «синдром сферического коня» и протокол заземления? Что еще стоит учесть основному агенту при формулировании промптов для тебя, чтобы минимизировать твоё желание строить избыточные абстракции?
2. **Надежность CLI-моста:** Какие скрытые риски или ограничения есть у неинтерактивного вызова `codex exec` (таймауты, лимиты контекста, фоновые демоны, формат вывода)?
3. **Модель `gpt-6.1-terra` vs `gpt-6.1-sol`:** В каких конкретно классах задач переход на Terra полностью оправдан, а в каких категорически необходимо форсировать Sol?
4. **Архитектурные пробелы:** Чего не хватает в текущей схеме для превращения этой связки в полноценный автономный дуэт сеньора и исследователя?
